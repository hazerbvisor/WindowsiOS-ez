# Implementation status

| Milestone | Implemented and checked | Pending |
| --- | --- | --- |
| 0. Baseline | Manual Codemagic workflow, version-aware native dependency cache, unsigned IPA packaging and artifact verification. Codemagic YAML schema and fixture tests passed. | Actual Xcode 27.2 device compilation, unsigned IPA emission, cold and warm build times, signing and baseline boot. |
| 1. Native foundation | SwiftUI library, existing Files-based VM, per-machine manifests and firmware state, prepared VM import, rename, configuration, duplicate, Files export and confirmed deletion. The app can start one prepared VM per process and accepts a guest power-button request. Memory preset math, disk format checks and persistence passed portable tests. | iPhone and iPad UI and document-provider tests, in-process engine teardown and switching, and a dedicated guest restart action. Restart from within Windows uses the existing guest path. |
| 2. JIT and memory | Native JIT settings for the existing authorized debugger workflow, readiness defined by the executable self-test, runtime memory diagnostics and signed entitlement inspection where available. Explicit RAM and vCPU settings are checked before start. Cache sizes beyond the existing 384 MiB mapping receive a clear error. A smaller selected cache uses only part of that mapping. | Integrated pairing and debugger helper, teardown and allocation recovery validation, and larger executable mappings. The 6 GiB/512 MiB, 8 GiB/1024 MiB and 10 GiB/1536 MiB presets are stored and rejected for launch by this build. Device acceptance of the 4.5 GiB/384 MiB preset also needs testing. Automatic retains upstream allocation as an explicit option. |
| 3. Windows installation | ISO import and HTTPS download with background transfer recovery, resume where provided by the server and iOS, progress, optional SHA-256, and format validation. The library validates UDF, the EFI loader’s ARM64 machine type and boot/install WIM metadata for build 26100. The wizard persists the draft and stages a sparse disk and separate UEFI variables. UDF fixture, invalid input and interrupted preparation tests passed. | Constructing a bootable installer disk on-device, verified WinPE provisioning and progress, signed driver injection, BCDBOOT, Secure Boot/TPM validation, standard OOBE, and first boot. A blank VM is labeled awaiting installation and cannot be launched. |
| 4. Stabilization | Portable Swift and C tests, malformed-media rejection, sparse-storage integrity, C static analysis, Swift parsing, assembly syntax validation for the existing ARM64 JIT trap object and manual test instructions. | Simulator and physical-device validation, sustained JIT load, audio/networking/OAuth regression, real download resume and Files export, full provisioning interruption tests, and release decisions. |

Twelve automated tests passed in Linux, including six Swift test groups and a synthetic UDF ISO test using the pinned libudfread release. The firmware validator also accepted the code and Microsoft-enrolled variable-store headers from Debian’s AAVMF package. Native SwiftUI and Objective-C iOS compilation are unverified. The upstream core tests could compile their C classification object with Linux Clang but stopped at Apple ARM64 assembly on the x86-64 host.
