# Implementation status

| Milestone | Implemented and checked | Pending |
| --- | --- | --- |
| 0. Baseline | Manual Codemagic workflow, version-aware native dependency cache, unsigned IPA packaging and artifact verification. Workflow schema and fixture tests passed. | Xcode 27.2 compilation, IPA emission, cold and warm build times, downstream signing and baseline boot. |
| 1. Native foundation | SwiftUI VM library, legacy Files-based VM, independent disks and firmware, validated import, rename, configuration, duplicate, Files export and confirmed deletion. The app can request the guest power button and run one VM per process. | iPhone and iPad UI and Files provider tests, in-process engine teardown and switching, and a dedicated host restart action. Windows' guest restart uses the existing PSCI path. |
| 2. JIT and memory | Settings and diagnostics for the existing authorized debugger. The app now requests the selected JIT capacity up to 1536 MiB and tries an exact guest RAM reservation while the debugger is attached. It retains the original 384 MiB low reserve, address checks and executable self-test. Failed allocations leave the preset selected and explain how to retry with Compatibility or Automatic. | Integrated pairing helper and physical allocation, branch reachability, flush and sustained-memory tests. The 10 GiB/1536 MiB combination is unverified. |
| 3. Windows installation | Windows ARM64 build 26100 ISO inspection and resumable HTTPS acquisition. The persisted wizard prepares a sparse target and a GPT installer with FAT32 EFI/WinPE and an exFAT payload. It customizes a copy of boot.wim to start Microsoft Setup and optionally passes a user-provided ARM64 NetKVM package to Setup for normal signature verification. The existing secondary NVMe slot attaches the installer read-only. The app requires ARM64 Windows boot files before switching to the primary disk. | Boot the actual Microsoft PE and verify Setup, driver injection, recovery, shutdown, and standard OOBE on an iPad. The original board has no TPM 2.0 device. Verify firmware Secure Boot and TPM support with standard Setup. The current flow uses Windows Setup's interactive UI, with no host-side DISM/BCDBOOT automation. |
| 4. Stabilization | Linux tests cover configuration, state recovery, media validation, firmware, GPT, FAT32, exFAT, WIM modification, driver preflight and artifacts. | Simulator/device results, real download resume and Files export, full provisioning interruption tests, audio/networking/OAuth checks, sustained high-memory testing, and release decisions. |

Seventeen automated tests passed in Linux, including seven Swift foundation groups, a UDF ISO fixture, and installer tests using independently read FAT32 and exFAT filesystems and a real WIM container with synthetic contents. The firmware validator also accepted the code and Microsoft-enrolled variable-store headers from Debian’s AAVMF package. Native SwiftUI and Objective-C iOS compilation are unverified. The upstream core tests compiled their C classification object and then stopped at Apple ARM64 assembly on the x86-64 host.
